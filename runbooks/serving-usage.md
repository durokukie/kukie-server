# API 사용량 저장·조회 (DURO-197)

V27은 프롬프트·답변·키 원문/해시 없이 중계 요청의 메타데이터만 PostgreSQL에 저장한다. GPU/DCGM/Prometheus 지표나 과금 원장과 별개다. 실제 데이터 경로는 기존 개인 키 → 공통 중계 → 고객 카운터 그대로다.

## 기록과 장애

중계 슬롯을 확보하고 외부 HTTP를 시작하기 전에 요청 UUID와 키/이용 권한/클러스터/사용자 ID, 모델, 시작·deadline 시각을 `IN_PROGRESS`로 커밋한다. 시작 기록에 실패하면 503 `SERVING_USAGE_UNAVAILABLE`로 거절하고 카운터를 호출하지 않는다. 인증·요청 형식·미허용 모델·로컬 동시 상한에서 거절한 요청은 중계 시작 건수에 포함하지 않는다. 모델 목록 GET도 중계 요청 건수에 포함한다.

종료 이벤트는 같은 요청 ID와 네 가지 소유 식별자가 일치하는 IN_PROGRESS 행만 갱신한다. 중복 전달·다른 키 식별자는 다시 합산하지 않는다. 상태는 COMPLETED/FAILED/TIMEOUT/CANCELLED/INCOMPLETE다. `httpStatus`는 최종 중계 처리 상태, `wireStatus`는 이미 전송한 HTTP 상태를 구분한다. SSE의 HTTP 200 이후 실패도 outcome으로 오류 집계한다. DB 트랜잭션은 HTTP 스트리밍 중 유지하지 않는다.

완료 쓰기에 실패하면 민감값 없는 고정 경고만 남기고 시작 기록을 유지한다. 서버 재시작·종료 쓰기 실패 등으로 남은 행은 기록 당시 전체 제한+60초 이후 조회에서 INTERRUPTED로 간주하고, 매 UTC 정시 정리 작업이 상태를 확정한다. 진행 중·미완료와 사용량 누락을 구분한다. 시작 기록은 내구성이 있지만 사고 때 정확한 토큰을 복원하거나 추론 응답 성공 여부를 보증할 수는 없다. DB 자체 백업·가용성은 기존 PostgreSQL 운영 정책을 따른다.

usage가 없거나 스트림/요청이 정상 완료되지 않았으면 `usageMissing`으로 표시한다. 확인된 토큰만 더하고 누락을 0토큰으로 추정하지 않는다. vLLM 스트리밍은 `stream_options.include_usage=true`가 필요하다. 미완료 스트림의 마지막 토큰 정보는 불완전할 수 있다. 금액·정확한 남은 토큰·예산 차단은 제공하지 않는다.

## 조회 API

모두 기존 Kukie 로그인 인증이다. 개인 API 키로 이 관리 API를 호출하지 않는다.

| 경로 | 범위 |
| --- | --- |
| GET `/serving/accesses/{accessId}/usage?from=YYYY-MM-DD&to=YYYY-MM-DD` | 본인이 소유한 해당 고객 클러스터의 사용 기록. 타 사용자·타 회사 제외 |
| GET `/clusters/{clusterId}/serving/usage?from=YYYY-MM-DD&to=YYYY-MM-DD&user={userId}` | 해당 팀 ADMIN만 전체 또는 사용자별 필터 |
| GET `/serving/accesses/{accessId}/info` | 본인 ACTIVE 권한의 연결 설정 여부·공개 API 주소·허용 모델·현재 운영 제한 |
| GET `/clusters/{clusterId}/serving/info` | 해당 ADMIN용 동일 공개 정보. 내부 카운터 주소/서비스 키 없음 |

기본 최근 7일, 최대 최근 90개 UTC 날짜(오늘 포함), 양 끝 날짜를 포함한다. 미래·역순·보관 범위 이전은 400이다. 응답은 `from,to,asOf,lastRecordedAt,retentionDays,totals,daily,byKey,byModel,byUser`다. totals는 요청·완료·오류/미완료·처리 중·확인된 입력/출력 토큰·집계 누락 건수다. 사용자 응답의 byUser는 빈 배열이다. 다중 집계는 REPEATABLE_READ의 같은 DB 스냅샷에서 읽는다. 갱신은 요청 종료 기록 커밋 후이며 화면의 새로고침으로 다시 조회한다.

기본 90일(오늘 및 이전 89일)을 보관하고 UTC 정시 작업으로 이전 기록을 제거한다. 재초대 시 같은 계정·같은 클러스터의 보관 기간 내 과거 사용량을 계속 조회한다. 취소된 과거 권한의 본인 기록 조회는 허용하되 새 호출·키 발급은 거절한다. 클러스터·사용자·키/이용 권한의 물리 삭제는 FK cascade로 관련 기록도 제거한다. 단순 키 폐기/권한 취소는 기록을 삭제하지 않는다.

## 공개 주소·한도

`SERVING_PORTAL_PUBLIC_API_BASE_URL`을 설정하면 그 공개 주소를 사용자에게 안내한다. 없으면 프론트가 기존 동일 출처 프록시 `<origin>/member/serving/v1`을 사용한다. 설정 여부는 연결 준비/모델 Ready 판정이 아니다. 내부 카운터 URL은 기존 ADMIN 전용 endpoint API에서만 조회한다.

키 5개·기본 90일/최대 365일과 현재 인스턴스별 동시·유휴/전체 제한을 안내한다. 토큰 예산과 여러 서버를 합친 전역 제한은 미지원이다. 화면은 이 운영 제한을 읽기 전용으로 보여주며 관리자별 미구현 한도 편집을 제공하지 않는다.

## 화면·검증·배포

프론트 `kukie-electron`의 GPU 상세 ‘대화’ 옆 ‘키 관리’에서 사용자 초대·이용 취소·키 폐기·사용량·카운터 연결을 관리한다. GPU가 꺼졌거나 에이전트 조회가 실패해도 키 관리 진입을 유지한다. 왼쪽 ArgoCD 아래 ‘내 API’는 팀 없는 계정도 열고, 가운데에는 본인이 수락한 제공 클러스터만, 오른쪽에는 본인 키·사용량·공통 주소/모델/호출 예제만 표시한다. 받은 API 초대도 이 화면에서 수락/거절한다. 초대 이메일은 아직 보내지 않는다.

키 원문은 발급 직후 모달에만 두고 닫기·대상/계정 전환 시 제거한다. localStorage·조회 캐시·로그에 보관하지 않는다. 서비스 키 입력은 password 필드이고 저장 후 비운다. 실패를 가짜 0사용량·빈 성공으로 바꾸지 않는다. 미연결/미집계/통신 실패를 구분한다.

저장·중복·회사/사용자 격리·UTC 기간·90일 보관·재시작 미완료·시작 기록 실패 차단을 시험한다. 실제 중계 SSE의 종료 이벤트가 DB에 기록되는 것도 통합 검증한다. 일회용 Testcontainers DB와 테스트 전용 인증의 실제 로컬 화면에서 A/B 전환, 키 발급/폐기, 초대/이용 취소를 확인했다. 그 임시 인증 코드는 커밋하지 않는다.

배포 순서는 서버(V24~V27) → 프론트다. 서버/프론트 PR·CI 통과와 실제 서비스 배포는 별개이며 공개 경로·TLS·고객 카운터/vLLM 종단 검증은 DURO-198에서 확인한다. 롤백은 이전 앱으로 되돌리고 사용량 테이블을 보존한다. 구 버전 중계로 롤백된 기간에는 새 기록이 생기지 않으므로 공백을 정상 0으로 간주하지 않는다.
